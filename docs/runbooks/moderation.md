# Moderation runbook — challenge entries

Operator guide for approving (or rejecting) **Same Species, Different Countries** challenge
photos. Built for the founder/admin role (PRD P5 / US-16). Ties to T7.7 admin UI,
T5.12 / T5.13 API, and **T10.2 Kingfisher Month go-live**.

## 1. Scope

| You moderate                                                         | You do **not** change here                          |
| -------------------------------------------------------------------- | --------------------------------------------------- |
| `app.challenge_entries` status: `pending` → `approved` or `rejected` | Exact coordinates (there are none in the queue)     |
| Reject reason text (required on reject)                              | Sensitivity tiers (use species admin; audit-logged) |
| Whether a photo is fit for the public gallery                        | Raw GBIF / `raw.*` data                             |

Public gallery rules (PRD US-13 AC3–AC4):

1. Entry must be **approved**.
2. Wall clock (or test clock) must be **on or after** `publish_after` (= submitted + **7 days**).
3. Public fields are **country + region only** — never a pin, cell, or lat/lng.

## 2. Kingfisher Month dates (go-live)

Canonical seed: `data/challenges/kingfisher-month.yaml` (upserted by `pnpm db:seed`).

| Field      | Value                                                                 |
| ---------- | --------------------------------------------------------------------- |
| Slug       | `kingfisher-month-2026-11`                                            |
| Title      | Kingfisher Month                                                      |
| Species    | Common kingfisher (_Alcedo atthis_) — `open` tier, challenge-eligible |
| Regions    | Scotland + Sindh                                                      |
| `startsOn` | **2026-11-01**                                                        |
| `endsOn`   | **2026-11-30**                                                        |
| Status     | `live` (API `active`)                                                 |

Submission window is those calendar days (UTC date string). Gallery visibility continues
after `endsOn` for approved entries past `publish_after`. Re-seed after editing YAML:

```bash
pnpm db:seed
# or: pnpm --filter @wildwindow/db exec tsx src/seed-challenges.ts
```

Confirm with `GET /v1/challenges/current` during the window (or the service clock in tests).

## 3. Access the queue

1. Sign in on the web app with an account that has `app.users.role = 'admin'`.
2. Open `/admin` (gated by `GET /v1/admin/session`).
3. Use the **Moderation** queue: filter `pending` / `approved` / `rejected` / all.
4. Each row shows place labels + photo key only — **no coordinates**.

Promote an operator (staging / local) with the worker CLI — never commit tokens:

```bash
pnpm worker make-admin --email you@example.com
```

API equivalents (Bearer Firebase ID token of an admin):

- `GET /v1/admin/challenge-entries?status=pending`
- `PATCH /v1/admin/challenge-entries/:id` with `{ "status": "approved" }` or
  `{ "status": "rejected", "rejectReason": "…" }`
- Every write lands in `app.audit_log` (`challenge_entry.moderate`).

## 4. Decision checklist (per entry)

Approve only when **all** are true:

- [ ] Photo is a **common kingfisher** (or the current challenge species).
- [ ] Country + region label match a beta home (Scotland / Sindh for Kingfisher Month).
- [ ] Pledge was accepted at submit (API enforces this; do not bypass in prod).
- [ ] No baiting / playback / nest disturbance is evident from the image or notes you have.
- [ ] Image is not abusive, illegal, or clearly off-topic.
- [ ] Photo key looks like a normal upload path (no surprise payloads).

Reject with a short, factual reason (shown to operators via admin; keep it professional).
Examples: `Wrong species`, `Unrelated image`, `Ethics concern — nest`.

**Do not** ask the submitter for a finer location. **Do not** paste coordinates into the
reject reason, audit notes, Slack, or GitHub.

## 5. Publish delay

- On submit, API sets `publish_after = now + 7 days` (`CHALLENGE_PUBLISH_DELAY_MS`).
- Approving early does **not** shorten the delay.
- `GET /v1/challenges/:slug/entries` returns only `approved` rows with
  `publish_after <= now`.
- Country counts on the challenge summary use the same filter.

## 6. Share card QA

Share cards are generated by the web app (`/api/og/forecast`, `/api/og/challenge/:entryId`).
Run this QA before calling a challenge go-live and after any OG or gallery change.

### Automated

```bash
pnpm --filter web test -- src/lib/og/share-card-qa.test.ts
pnpm --filter web test -- src/lib/og/og-images.test.ts
pnpm --filter mobile test -- share-card
```

### Manual (staging)

1. Approve a test entry; advance time (or wait) past `publish_after`.
2. Open `/challenges/kingfisher-month-2026-11` — entry visible under the right country tab.
3. Open `/api/og/challenge/<entryId>?slug=kingfisher-month-2026-11`:
   - PNG **1080×1080**
   - Shows species + **country/region** place line only
   - **No** H3 cell, lat/lng, or pin language
4. Forecast card `/api/og/forecast?taxonId=…&cell=…&start=…`:
   - PNG **1080×1920**
   - Uses area label / Window score — never raw coordinates on the image
5. Mobile share preview (S-15): card URL has no lat/lng; share downloads the PNG.

Automated No-Pin gates live in `apps/web/src/lib/og/public-safe.ts` and
`apps/web/src/lib/og/share-card-qa.test.ts` (T10.2).

## 7. Dry run (acceptance — T10.2)

Automated: `apps/api/src/challenges/kingfisher-month-golive.e2e.test.ts`.

It submits **5** Kingfisher Month test entries (Scotland + Sindh mix), approves them,
and advances a **test clock**:

| Clock                            | Expectation                                                   |
| -------------------------------- | ------------------------------------------------------------- |
| Submit at `T0`                   | Status `pending`; `publish_after = T0 + 7d`                   |
| After approve, clock `< T0 + 7d` | Public gallery still empty                                    |
| Clock `>= T0 + 7d`               | All 5 entries listed; country/region only; `assertPublicSafe` |

```bash
pnpm --filter api test -- kingfisher-month-golive
```

Requires PostGIS (CI or `pnpm db:up` locally). Do **not** run the dry run against
production user data.

## 8. Privacy and incidents

- Any location leak (pin, EXIF GPS, cell in a public card) is **P0** / `privacy`.
  File with `.github/ISSUE_TEMPLATE/privacy_report.yml` — describe screen and region in
  words; never paste exact coordinates.
- Queue and public responses must keep passing `assertPublicSafe`.
- Strip GPS EXIF before upload (client) and re-check on the server.
